# Unified Retrospective Low-Resolution + Undersampling Reconstruction
## Implementation To-Do for Wave-MPRAGE and Wave-GRE-Flow-Comp

Status: planning / implementation pending  
Date: 2026-08-18

Upstream repositories:

- Wave-MPRAGE: https://github.com/HarmonizedMRI/wave-mprage
- Wave-GRE-Flow-Comp: https://github.com/HarmonizedMRI/wave-gre-flow-comp

---

# 1. Goal

Build one retrospective reconstruction repository that can consume outputs from either:

- `wave-mprage`
- `wave-gre-flow-comp`

and perform, in batch:

1. retrospective phase-encoding low-resolution synthesis;
2. additional retrospective undersampling;
3. target-resolution Wave PSF generation;
4. target-resolution coil-sensitivity handling;
5. BART Wave-CAIPI reconstruction;
6. magnitude and optional phase NIfTI generation.

The implementation should avoid rerunning expensive upstream preprocessing for every retrospective case.

The new design should treat the upstream BART export as the preferred reusable interface rather than depending directly on internal cache filenames such as raw PSF coefficient files or sequence-specific CSM cache names.

# 3. Important upstream changes that the new implementation must account for

## 3.1 BART input export

Both upstream repositories now support:

```text
--save-bart-inputs
```

and use the same BART I/O/export contract.

Current canonical exported native-array conventions are:

```text
wave_kspace:
    [RO_os, LIN, PAR, echo, coil]

calibrated_psf:
    [echo, RO_os, LIN, PAR]

coil_sens:
    [coil, RO, LIN, PAR]

kspace_calib:
    [RO, LIN, PAR, coil]
```

BART-facing outputs use:

```text
READ, PHS1, PHS2, COIL, MAPS
```

The retrospective code should adopt this same convention.

## 3.2 BART manifest

The source `manifest.json` contains:

- BART format;
- dimension ordering;
- coil-sensitivity basename and shape;
- calibration-k-space basename and shape;
- one entry per echo;
- Wave k-space basename and shape;
- PSF basename and shape;
- Wave k-space L2 norm.

The retrospective code should parse this manifest and treat it as authoritative for echo ordering and source BART filenames.

## 3.3 Flexible BART Wave reconstruction

The upstream BART wrapper now supports direct passthrough options to:

```text
bart ecalib
bart wave
```

including regularization choices such as:

```text
-w          wavelet
-l          locally low rank
-r VALUE    regularization strength
-b VALUE    LLR block size
-f          FISTA
-H          Hogwild
-i VALUE    iteration count
-t VALUE    tolerance
-g          GPU
```

The retrospective pipeline should mirror this interface rather than hard-code a single BART reconstruction configuration.

## 3.4 BART internal normalization

`bart wave` internally normalizes the supplied Wave k-space.

The upstream BART-to-NIfTI converters restore the input k-space norm afterward.

The retrospective code must preserve this behavior.

For every retrospective echo, record the norm of the actual **retrospectively cropped and undersampled** BART k-space in the target manifest.

Do not reuse the source k-space norm after retrospective processing.

## 3.5 ESPIRiT changes

Both upstream repos now support:

```text
3d
slice2d
```

ESPIRiT calibration.

The implementations differ in support-mask details:

- Wave-MPRAGE sagittal slice2d uses a special superior-inferior whole-plane support guard.
- Wave-GRE slice2d uses its own logical-RO support detection.
- CSM cache filenames now depend on calibration mode.

The retrospective repository should avoid depending on those cache naming conventions.

Use the final exported:

```text
coil_sens
```

when target maps are derived from upstream maps.

## 3.6 PSF coefficient processing

Upstream PSF calibration now supports processing choices including:

```text
smooth
sine-line
```

and includes additional PSF fitting, diagnostics, and fixes.

The retrospective code should not reproduce or partially duplicate those upstream PSF-calibration steps.

Instead, start from the **final exported calibrated PSF**.

## 3.7 NIfTI behavior

Current upstream behavior includes:

- geometry validation against TWIX/Pulseq;
- current axis/orientation conventions;
- magnitude normalization;
- phase output;
- BART norm restoration;
- no extra readout crop for BART output.

The old retrospective NIfTI path is therefore out of date and must be replaced.

# 4. Unified internal data model

Canonicalize both acquisitions to the following internal representation.

```text
wave_kspace:
    [RO_os, LIN, PAR, ECHO, COIL]

psf:
    [ECHO, RO_os, LIN, PAR]

coil_sens:
    [COIL, RO, LIN, PAR]

kspace_calib:
    [RO, LIN, PAR, COIL]

sampling_mask:
    [ECHO, LIN, PAR]   # inferred in memory only
```

## MPRAGE

Treat MPRAGE as:

```text
ECHO = 1
```

Do not write separate single-echo-specific reconstruction logic in the common core.

## GRE

Keep the full echo dimension.

Each echo may have an echo-specific calibrated PSF.

The coil sensitivity maps and BART calibration k-space are shared across echoes.

Create small adapters rather than embedding sequence-specific assumptions throughout the core.

Recommended:


Each adapter should provide:

- FOV and source matrix;
- source acceleration;
- number of echoes;
- NIfTI geometry/orientation handling;
- sequence-specific metadata;
- sequence-specific magnitude normalization policy;
- source validation.

The shared retrospective code should not directly hard-code sagittal or transverse geometry.

# 6. Axis conventions

## Wave-MPRAGE

Current validated sagittal convention:

```text
logical RO  = physical z
logical LIN = physical y
logical PAR = physical x
```

Therefore physical resolution requests map as:

```text
physical X -> logical PAR
physical Y -> logical LIN
physical Z -> logical RO
```

Readout resolution must remain unchanged.

Example:

```text
source physical resolution:
1 x 1 x 1 mm

requested:
1.5 x 1 x 1 mm
```

is valid for MPRAGE because physical X is a phase-encoding dimension.

## Wave-GRE

Current transverse convention:

```text
logical RO  = physical x
logical LIN = physical y
logical PAR = physical z
```

Therefore physical resolution requests map as:

```text
physical X -> logical RO
physical Y -> logical LIN
physical Z -> logical PAR
```

Readout resolution must remain unchanged.

Thus:

```text
source:
1 x 1 x 1 mm

requested:
1.5 x 1 x 1 mm
```

must be rejected for current GRE because physical X is readout.

Valid GRE LR examples include:

```text
1 x 1.5 x 1 mm
1 x 1 x 1.5 mm
1 x 1.5 x 1.5 mm
```

# 9. Target matrix calculation

For every phase-encoding physical dimension:

```text
Ntarget = round(FOV_mm / requested_resolution_mm)
```

Equivalent form:

```text
Ntarget = round(
    Nsource * source_resolution_mm / requested_resolution_mm
)
```

Readout matrix must remain unchanged.

After integer rounding, calculate actual achieved resolution:

```text
achieved_resolution_mm = FOV_mm / Ntarget
```

Record both:

```text
requested_resolution_mm
achieved_resolution_mm
```

in metadata.

# 10. Case folder naming

Use **actual achieved physical XYZ resolution**, rounded to at most two decimal places.

Remove unnecessary trailing zeroes.

Examples:

```text
res1x1x1mm_R3x1
res1.5x1x1mm_R3x1
res1.5x1x1mm_R3x2
res1x1.5x1mm_R3x2
```

Formatting helper:

```python
def format_resolution(value: float) -> str:
    return f"{value:.2f}".rstrip("0").rstrip(".")
```

Do not derive geometry from the folder name.

The folder name is user-facing only.

Store full-precision achieved resolution in `case_info.json`.

## Collision handling

First deduplicate cases that resolve to the same:

```text
target logical matrix
target acceleration
```

If two different matrices still produce the same rounded folder name, append a matrix suffix.

Example:

```text
res1.5x1x1mm_R3x1
res1.5x1x1mm_R3x1_Nlin170_Npar256
```

# 12. Sampling mask inference

Do not save sampling masks.

Infer them from each echo of source Wave k-space once.

Use line energy across readout and coil:

```python
line_energy = np.sum(
    np.abs(kspace_echo) ** 2,
    axis=(0, 3),
)
```

Use a small relative numerical threshold rather than assuming only exact zeros if desired.

Result:

```text
[LIN, PAR]
```

Keep all masks in memory only.

For multi-echo GRE, infer one mask per echo.

Verify whether all echoes share the same nominal acceleration pattern.

Do not require exact line-by-line equality if occasional zero-value acquired lines are possible, but acceleration inference must be robust and validated.

# 13. Source acceleration inference

Infer nominal source:

```text
Ry
Rz
```

from the source sampling mask, center-referenced to:

```text
LIN center = Nlin // 2
PAR center = Npar // 2
```

Requirements:

- acquired center line must be preserved;
- identify regularly sampled lattice relative to center;
- tolerate edge truncation from finite matrix;
- reject ambiguous or irregular patterns rather than guessing.

Expected common examples:

```text
R1x1
R2x1
R3x1
R3x2
```

# 14. Rules for additional retrospective undersampling

Only add acceleration along a dimension that is originally fully sampled.

Allowed:

```text
source R1x1 -> target R2x1
source R1x1 -> target R2x2
source R3x1 -> target R3x2
```

Rejected:

```text
source R3x1 -> target R6x1
source R3x2 -> target R3x3
source R2x2 -> target R4x2
```

In other words:

```text
if source R_axis > 1:
    target R_axis must equal source R_axis
```

and:

```text
if source R_axis == 1:
    target R_axis may be >= 1
```

Every added undersampling lattice must be centered relative to:

```text
Ntarget // 2
```

for the target cropped matrix.

Final mask:

```text
case_mask =
    cropped_source_mask
    AND
    added_retrospective_mask
```

Apply exact zeros to unacquired k-space positions.

This is required because BART `wave` derives the sampling mask from non-zero k-space.

# 15. Retrospective low-resolution crop

Only crop phase-encoding dimensions.

Do not crop readout.

For target logical:

```text
Nlin_target
Npar_target
```

use center crops:

```python
llin = Nlin0 // 2 - Nlin_target // 2
rlin = llin + Nlin_target

lpar = Npar0 // 2 - Npar_target // 2
rpar = lpar + Npar_target
```

Apply the same phase crop to:

- Wave k-space;
- source mask;
- target CSM derivation;
- calibration k-space when appropriate.

PSF must be **re-evaluated** on the target normalized spatial coordinate grid rather than simply center-cropped in image-space dimensions.

# 16. PSF redesign

## Do not depend on raw `a/b/c` cache files

The old retrospective implementation reconstructs PSF from upstream coefficient `.npy` files.

Replace that design.

The source BART export already contains the final calibrated PSF after upstream:

- theoretical Wave trajectory;
- sign convention;
- raw PSF fit;
- `smooth` or `sine-line` processing;
- phase correction;
- echo-specific GRE trajectory behavior.

Use the final PSF as the source of truth.

## Phase-plane model

For each echo and each oversampled readout location, the calibrated PSF is expected to have the form:

```text
P(kx, lin, par)
=
exp(
    i * [
        alpha(kx) * lin_norm
        + beta(kx) * par_norm
        + gamma(kx)
    ]
)
```

where:

```text
lin_norm =
    (arange(Nlin) - Nlin/2) / Nlin

par_norm =
    (arange(Npar) - Npar/2) / Npar
```

## Extract total phase-plane coefficients

Implement robust extraction of:

```text
alpha[kx]
beta[kx]
gamma[kx]
```

from the source **complex PSF**.

Prefer adjacent complex phase ratios rather than direct wrapped-angle plane fitting.

Conceptually:

```python
dlin = psf[:, 1:, :] * np.conj(psf[:, :-1, :])
dpar = psf[:, :, 1:] * np.conj(psf[:, :, :-1])
```

Estimate mean phase increments using a circular/complex mean.

Account for normalized coordinate spacing:

```text
Δlin_norm = 1 / Nlin
Δpar_norm = 1 / Npar
```

Then estimate the constant complex phase after removing both slopes.

## Source-resolution identity validation

Before accepting extracted coefficients:

1. regenerate the source PSF on the original source grid;
2. compare regenerated complex PSF to exported source PSF;
3. calculate:
   - relative complex L2 error;
   - maximum complex error;
   - phase residual statistics;
4. stop if the error is above a strict tolerance.

Do not silently fall back to approximate PSF handling.

## Target PSF

For every retrospective matrix:

```python
lin_norm_target = (
    np.arange(Nlin_target) - Nlin_target / 2
) / Nlin_target

par_norm_target = (
    np.arange(Npar_target) - Npar_target / 2
) / Npar_target
```

Evaluate the extracted source phase planes on this target grid.

Keep:

```text
RO_os
echo count
```

unchanged.

Result:

```text
[ECHO, RO_os, Nlin_target, Npar_target]
```

# 17. Coil-sensitivity strategy

Support two modes.

## 17.1 `--maps-source existing`

Recommended default.

Input:

```text
bart_inputs/coil_sens
```

BART shape:

```text
[RO, LIN, PAR, COIL, 1]
```

Convert internally to:

```text
[COIL, RO, LIN, PAR]
```

Interpolate only along target PE dimensions.

Do not change RO.

Suggested workflow:

1. preserve complex values;
2. interpolate real and imaginary components;
3. return to complex;
4. RSS normalize across coil dimension;
5. validate finite values.

Result:

```text
[COIL, RO, Nlin_target, Npar_target]
```

Export back to BART:

```text
[RO, Nlin_target, Npar_target, COIL, 1]
```

This route avoids rerunning ESPIRiT for every batch case.

## 17.2 `--maps-source bart`

Optional target-specific BART ESPIRiT.

Start from:

```text
kspace_calib
```

Center crop its PE dimensions to target matrix.

Important:

- verify that target PE dimensions are large enough to contain the non-zero ACS support;
- do not truncate actual ACS;
- preserve RO and coil dimensions.

Then run:

```text
bart ecalib -m 1 ...
```

using user-provided:

```text
--ecalib-options
```

For the first implementation, force:

```text
-m 1
```

to remain consistent with current upstream BART-to-NIfTI behavior.

Reject user attempts to pass another `-m` value.

Always use equivalent of:

```text

```

for BART results.

# 23. Magnitude normalization policy

## MPRAGE

Match current upstream behavior:

1. take magnitude;
2. consider positive finite voxels;
3. compute 99th percentile;
4. divide magnitude by that percentile;
5. do not clip.

Output magnitude units:

```text
relative
```

Phase remains:

```text
radians
```

## GRE

Preserve relative echo intensity.

Workflow:

1. restore BART k-space norm independently for every echo;
2. calculate one magnitude p99 normalization scale from echo 1;
3. apply that **same scale** to every echo;
4. do not normalize each echo independently;
5. do not alter phase.

Store shared normalization scale in metadata.

# 36. Compatibility policy

Initial release should target the **current** upstream BART export contract.

Do not spend substantial complexity supporting every old pre-BART-output layout.

If legacy support is needed later, implement it as an explicit importer:

```text
legacy_source.py
```

which converts historical root-level `.npy` files into the same common internal model.

Keep legacy handling outside the primary pipeline.

# 37. Non-goals for first implementation

Do not include yet:

- [ ] arbitrary readout-resolution reduction;
- [ ] retrospective readout undersampling;
- [ ] multi-map ESPIRiT (`-m2` or higher);
- [ ] automatic recomputation from raw `.dat` when BART inputs are missing;
- [ ] support for arbitrary orientations beyond currently validated MPRAGE SAG and GRE TRA;
- [ ] GRAPPA reconstruction;
- [ ] modification of original upstream output files;
- [ ] persistent sampling-mask files.

These can be added later after the common BART-based pipeline is validated.

# 38. Key design principles

1. **Prepare once, synthesize many.**  
   Upstream calibration and coil compression should not be repeated for every retrospective case.

2. **Use final upstream products, not fragile intermediate filenames.**  
   The BART input contract is the preferred interface.

3. **MPRAGE is a one-echo special case of the common multi-echo model.**

4. **Keep physical resolution user-facing and logical axes internal.**

5. **Never change readout resolution in the first version.**

6. **Use achieved physical resolution in folder names.**

7. **Do not save sampling masks.**

8. **Default to storage-efficient intermediates.**

9. **Use BART for reconstruction so regularization is flexible.**

10. **Preserve current upstream NIfTI intensity and geometry behavior.**

11. **Validate source-resolution identity before trusting any LR synthesis.**

12. **Fail clearly rather than silently guessing when source geometry, acceleration, ACS support, or PSF assumptions are ambiguous.**

# 39. Suggested first implementation milestone

A good first milestone is:

```text
MPRAGE + GRE common source loader
        ↓
identity target case
        ↓
PSF source-identity reconstruction
        ↓
existing-map CSM path
        ↓
BART input regeneration
        ↓
BART Wave recon
        ↓
target-aware NIfTI
```

with **no actual LR crop yet**.

Once both upstream acquisition types reproduce their own source-resolution BART result through the new common pipeline, add:

```text
LR crop
```

then:

```text
additional undersampling
```

This isolates architecture and convention bugs from retrospective-synthesis bugs.
